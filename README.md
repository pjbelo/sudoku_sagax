# Sudoku Sagax

A Flutter sudoku game published under the **Sagax Games** brand (developer:
Tekinsight — Information Technologies). Nine difficulty levels, notes, timer,
hints, an options screen and a local scoreboard. It shares architecture, UI and
design with its sister games **Memorex** and **Slidox**.

Targets **iOS** and **Android**.

- App title: `Sudoku Sagax`
- Bundle id / applicationId: `com.tekinsight.sudokusagax`
- Version: see `version:` in [pubspec.yaml](pubspec.yaml) (currently `1.0.0+1`)

## Gameplay

- **9 levels** in 5 bands (Beginner → Expert), from 46 givens down to 24.
  Every puzzle is generated on the fly and has exactly **one solution**.
  Levels 1–5 can be solved with "singles" alone; levels 7–9 always need
  candidate elimination. See [docs/research.md](docs/research.md) for the
  rationale.
- Pick a cell, then a number. Entering the same number again clears the cell.
  Placing a number removes it from the notes in its row, column and box.
- **Notes** mode pencils in candidates as a 3×3 mini-grid in the cell.
- **Undo** and **Erase**. The number pad shows how many of each digit are left.
- **Timer** with pause. The clock also stops when the app goes to the background.
- **Hint** fills in a correct number (the selected cell, or a random open one)
  at a cost of **+30 s**.
- **Scoreboard**: the top 10 times per level, with hints and mistakes. Ranked by
  time, then hints, then mistakes.
- Keyboard play on desktop and tablets: digits, Backspace/Delete, arrow keys,
  `N` for notes.
- Portrait layout for phones; side-by-side layout with a 3×3 keypad in landscape.

### Options

| Option | Default | Effect |
|---|---|---|
| Sound | **ON** | Music and sound effects |
| Timer | **ON** | Shows the clock (time is always recorded for the scoreboard) |
| Show errors | **OFF** | Marks wrong numbers in red and shows a Mistakes counter |
| Hint button | **ON** | Shows the Hint (+30 s) button |

Options, the chosen language and the scoreboard persist across restarts
(`shared_preferences`).

## Getting started

```bash
flutter pub get
flutter run --release        # run on a connected device
flutter analyze              # static analysis (flutter_lints)
flutter test                 # unit + widget tests
```

Requires the Flutter stable channel with Dart SDK `^3.13.5` (developed against
Flutter 3.47.x).

### Theming

Use the `AppColors` constants and `sagaxTheme` from
[lib/sagax_theme.dart](lib/sagax_theme.dart). Fonts come from `google_fonts`,
bundled in `google_fonts/`: **Exo 2** (Regular/SemiBold/Bold) for headings and
digits, **Inter** (Light/Regular/Medium/Bold) for body text. A new weight needs
its `.ttf` added there first.

The logo is drawn in code ([lib/widgets/sudoku_logo.dart](lib/widgets/sudoku_logo.dart))
until a designed PNG exists, like `slidox-transp.png`.

### App icon

A neon 3×3 sudoku box with the glowing centre "9", drawn in code in
[tool/store/app_icon_test.dart](tool/store/app_icon_test.dart). It produces a
full icon (iOS, legacy Android), Android adaptive foreground and background
layers, and a monochrome layer for Android 13+ themed icons.
`tool/store/app_icon.sh` renders the layers, runs `flutter_launcher_icons` (see
[flutter_launcher_icons.yaml](flutter_launcher_icons.yaml)) and writes the
512×512 Play Store icon.

### Audio

[`AudioService`](lib/services/audio_service.dart) owns one music player and one
SFX player. Playback is gated on the **Sound** option and on silent mode. iOS
uses the `ambient` category (respects the mute switch). Android polls ringer
mode over `MethodChannel('com.tekinsight.sudokusagax/ringer')`, implemented in
[MainActivity.kt](android/app/src/main/kotlin/com/tekinsight/sudokusagax/MainActivity.kt).

## Localization

Uses Flutter's `gen-l10n` (configured by [l10n.yaml](l10n.yaml)).

- Source strings: `lib/l10n/app_<locale>.arb`; `app_en.arb` is the template.
- Supported locales: **en, pt, es, fr, de**.
- `app_localizations*.dart` are generated and committed. After editing any
  `.arb`, run `flutter gen-l10n`.

## Testing

### Automated tests

```bash
flutter analyze    # static analysis — must report "No issues found!"
flutter test       # 41 tests: generator, game model, services, UI flows
```

The tests cover puzzle generation (uniqueness, clue counts and technique for
all 9 levels), the game rules (notes, undo, hints, mistakes), settings and
scoreboard persistence, and full UI flows (solving a level with hints, options,
pause, leaving a game).

### On a physical device

List what Flutter can see with `flutter devices`, then run with
`-d <device-id>`. Use **debug** (the default) while developing, for hot reload.
Use `--release` to judge real performance and sound, and to keep the app
installed after you unplug.

**Android**

1. On the phone: *Settings → About phone →* tap **Build number** 7 times, then
   *Settings → System → Developer options →* enable **USB debugging**.
   For a cable-free setup on Android 11+, enable **Wireless debugging** and pair
   with `adb pair <ip>:<port>`.
2. Connect it and accept the "Allow USB debugging?" prompt.
3. Run it:

   ```bash
   flutter run -d <device-id>              # debug, hot reload
   flutter run -d <device-id> --release    # release build
   ```

4. To hand an APK to a tester (they must allow installs from unknown sources):

   ```bash
   flutter build apk --release
   adb install build/app/outputs/flutter-apk/app-release.apk
   ```

**iOS** (needs a Mac with Xcode)

1. Open `ios/Runner.xcworkspace` in Xcode once. Under *Runner → Signing &
   Capabilities*, keep **Automatically manage signing** with team
   `RC95G6W642`. Xcode registers `com.tekinsight.sudokusagax` for development.
2. Connect the iPhone/iPad by cable and tap **Trust This Computer**. On iOS 16+,
   enable *Settings → Privacy & Security → **Developer Mode*** (the device
   restarts).
3. Run it:

   ```bash
   flutter run -d <device-id> --release
   ```

   On iOS, debug builds can't be opened from the home screen once the device
   is disconnected. Use `--release` (or `--profile`) for standalone play.

**Simulators / emulators:** `open -a Simulator` (iOS) or
`flutter emulators --launch <id>` (Android), then `flutter run`.

**Worth checking by hand on a device:** sound with the mute switch on/off
(iOS) and in silent mode (Android); that the timer pauses when the app goes to
the background; portrait phones and landscape tablets; all 5 languages.

## Publishing

### Before every release

1. Bump `version:` in [pubspec.yaml](pubspec.yaml). The format is
   `<version name>+<build number>` (e.g. `1.0.0+1` → `1.0.1+2`). **Both stores
   reject a build number that was already uploaded.**
2. `flutter analyze && flutter test`.
3. Smoke-test a `--release` build on a real iPhone and Android phone.

### Google Play (Android)

**One-time setup**

1. **Reuse the company upload keystore**, the same one Memorex and Slidox
   use. With Play App Signing, Google holds a separate app-signing key for
   each app; the upload key only proves to Google that an upload comes from
   Tekinsight. Copy both files from a sister project, or from the team
   password manager:

   ```bash
   cp ../slidox/android/app/upload-keystore.jks android/app/
   cp ../slidox/android/key.properties android/
   ```

   `android/key.properties` must contain the following. Both files are
   gitignored, so never commit them:

   ```properties
   storePassword=<store password>
   keyPassword=<key password>
   keyAlias=upload
   storeFile=upload-keystore.jks
   ```

   `storeFile` is resolved relative to `android/app/`.

   > Create a separate key for this app only if it may be sold or transferred
   > to another developer on its own:
   > `keytool -genkey -v -keystore android/app/upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload`.
   > If the upload key is ever lost or leaked, the account owner can request an
   > upload-key reset in Play Console.

2. Check the build picks the key up.
   [android/app/build.gradle.kts](android/app/build.gradle.kts) reads
   `android/key.properties`. Without it, release builds fall back to the debug
   key and Gradle warns `android/key.properties not found`. **Never upload such
   a build.**
3. In [Play Console](https://play.google.com/console): **Create app** → name
   *Sudoku Sagax*, type *Game*, *Free*. Keep **Play App Signing** on (the
   default): Google holds the app-signing key and you sign uploads with the
   upload key.
4. Complete **App content**:
   - privacy policy URL;
   - ads: none;
   - content rating questionnaire;
   - target audience;
   - **Data safety**: no data collected or shared, since options and scores
     stay on the device. Revisit this when Firebase is added.
5. Fill in the **Store listing**:
   - category *Games › Puzzle*;
   - short and full description in en/pt/es/fr/de;
   - 512×512 icon: `docs/google-play/icon-512.png`;
   - 1024×500 feature graphic: `docs/google-play/feature-graphic-<lang>.png`,
     one per language. Regenerate them with `tool/store/feature_graphic.sh`
     after changing the logo, tagline or board style;
   - at least 2 phone screenshots, and tablet screenshots too.

**Each release**

```bash
flutter build appbundle --release
open build/app/outputs/bundle/release/      # app-release.aab
```

In Play Console, go to *Test and release → Testing → **Internal testing** →
Create new release*. Upload the `.aab`, add release notes, and roll out. Once it
has been tested, promote the release to *Closed testing* or *Production*.

> If the developer account is a **personal** account created after November
> 2023, Google requires a closed test with at least 12 testers for 14 days
> before you can apply for production access. Organisation accounts are exempt.

### App Store (iOS)

**One-time setup**

1. Apple Developer Program membership (team `RC95G6W642`). The App ID
   `com.tekinsight.sudokusagax` must exist under *Certificates, Identifiers &
   Profiles → Identifiers*. Xcode's automatic signing usually creates it.
2. In [App Store Connect](https://appstoreconnect.apple.com): *Apps → **+** →
   New App*:
   - platform *iOS*;
   - name *Sudoku Sagax* (store names must be unique; *SAGAX: Sudoku* is the
     fallback in the sibling apps' style);
   - bundle ID `com.tekinsight.sudokusagax`;
   - SKU e.g. `sudokusagax`.
3. Complete:
   - **App Privacy**: *Data Not Collected* until Firebase is added;
   - **Age Rating**: 4+;
   - category *Games / Puzzle*;
   - price *Free*;
   - privacy policy URL.
4. Screenshots are required for **iPhone 6.9"** (1320×2868) **and iPad 13"**
   (2064×2752), because the app supports both (`TARGETED_DEVICE_FAMILY = 1,2`).

**Each release**

```bash
flutter build ipa --release
open build/ios/ipa/                          # Sudoku Sagax.ipa
```

1. Upload the `.ipa` with Apple's **Transporter** app (drag and drop). The
   alternative is opening `build/ios/archive/Runner.xcarchive` in Xcode and
   choosing *Organizer → Distribute App → App Store Connect*.
   `ITSAppUsesNonExemptEncryption` is already `NO` in
   [Info.plist](ios/Runner/Info.plist), so there is no export-compliance
   question.
2. After processing (usually 10–30 min), the build appears under
   **TestFlight**. Internal testers can install it at once; external testers
   need a short Beta App Review.
3. On the *App Store* tab, create the version, select the build, fill in
   *What's New*, and **Submit for Review**.

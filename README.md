# Sudoku Sagax

A Flutter sudoku game published under the **Sagax Games** brand (developer:
Tekinsight — Information Technologies). Nine difficulty levels, notes, timer,
hints, an options screen and a local scoreboard. It shares architecture, UI and
design with its sister games **Memorex** and **Slidox**.

Targets **iOS** and **Android**.

- App title: `Sudoku Sagax`
- Bundle id / applicationId: `com.tekinsight.sudoku` (iOS and Android). The
  Android namespace and Kotlin package stay `com.tekinsight.sudokusagax`; they
  are internal and not seen by the stores.
- Website: <https://sudoku.sagax-games.com>
- Stores: [Google Play](https://play.google.com/store/apps/details?id=com.tekinsight.sudoku) ·
  [App Store](https://apps.apple.com/app/id6820541123) (Apple ID `6820541123`)
- Version: see `version:` in [pubspec.yaml](pubspec.yaml) (currently `1.0.0+1`)

## Gameplay

- **9 levels** in 5 bands (Beginner → Expert), from 46 givens down to 24.
  Every puzzle is generated on the fly and has exactly **one solution**.
  Levels 1–5 can be solved with "singles" alone; levels 7–9 always need
  candidate elimination. See [docs/research.md](docs/research.md) for the
  rationale.
- Pick a cell, then a number. Entering the same number again clears the cell.
  Placing a number removes it from the notes in its row, column and box.
- **Notes** mode pencils in candidates as a 3×3 mini-grid in the cell.
- **Undo** and **Erase**. The number pad shows how many of each digit are left.
- **Timer** with pause. The clock also stops when the app goes to the background.
- **Hint** fills in a correct number (the selected cell, or a random open one)
  at a cost of **+30 s**.
- **Scoreboard**: the top 10 times per level, with hints and mistakes. Ranked by
  time, then hints, then mistakes.
- Keyboard play on desktop and tablets: digits, Backspace/Delete, arrow keys,
  `N` for notes.
- Portrait layout for phones; side-by-side layout with a 3×3 keypad in landscape.

### Options

| Option | Default | Effect |
|---|---|---|
| Sound | **ON** | Music and sound effects |
| Timer | **ON** | Shows the clock (time is always recorded for the scoreboard) |
| Show errors | **OFF** | Marks wrong numbers in red and shows a Mistakes counter |
| Hint button | **ON** | Shows the Hint (+30 s) button |

Options, the chosen language and the scoreboard persist across restarts
(`shared_preferences`).

Flutter 3.47.x).

### Theming

Use the `AppColors` constants and `sagaxTheme` from
[lib/sagax_theme.dart](lib/sagax_theme.dart). Fonts come from `google_fonts`,
bundled in `google_fonts/`: **Exo 2** (Regular/SemiBold/Bold) for headings and
digits, **Inter** (Light/Regular/Medium/Bold) for body text. A new weight needs
its `.ttf` added there first.

The home-screen logo is `assets/images/sudoku-sagax-transp.png` (transparent,
like `slidox-transp.png`). It is rendered from
[lib/widgets/sudoku_logo.dart](lib/widgets/sudoku_logo.dart) at 5× size. After
changing the design, regenerate it with
`flutter test tool/store/logo_test.dart --update-goldens`.

The Sudoku Sagax logo on Sagax midnight navy (`#0F172A`), on both platforms:

- **iOS:** [LaunchScreen.storyboard](ios/Runner/Base.lproj/LaunchScreen.storyboard)
  with `LaunchImage` (300 pt wide, @1x/@2x/@3x in

  there is no white flash.

All the logo images are scaled from `assets/images/sudoku-sagax-transp.png`;
regenerate them with `sips` if the logo changes.

### App icon

A neon 3×3 sudoku box with the glowing centre "9", drawn in code in
[tool/store/app_icon_test.dart](tool/store/app_icon_test.dart). It produces a
full icon (iOS, legacy Android), Android adaptive foreground and background
layers, and a monochrome layer for Android 13+ themed icons.
`tool/store/app_icon.sh` renders the layers, runs `flutter_launcher_icons` (see
[flutter_launcher_icons.yaml](flutter_launcher_icons.yaml)) and writes the
512×512 Play Store icon.

### Audio

[`AudioService`](lib/services/audio_service.dart) owns one music player and one
SFX player. Playback is gated on the **Sound** option and on silent mode. iOS
uses the `ambient` category (respects the mute switch). Android polls ringer
mode over `MethodChannel('com.tekinsight.sudokusagax/ringer')`, implemented in
[MainActivity.kt](android/app/src/main/kotlin/com/tekinsight/sudokusagax/MainActivity.kt).

## Firebase

Project **`sudoku-sagax-games`**, with one Android and one iOS app, both
`com.tekinsight.sudoku`. It is set up by
[lib/main.dart](lib/main.dart) before `runApp`, **on Android and iOS only**:

- **Core**.
- **Analytics** for screen views and gameplay events.
- **Crashlytics**, wired to `FlutterError.onError` and
  `PlatformDispatcher.onError`. Collection is off in debug builds, so dev
  crashes stay out of the dashboard.

On desktop and web Firebase is skipped, so `flutter run -d macos` still works.

Events go through [`AnalyticsService`](lib/services/analytics_service.dart),
which does nothing until Firebase is initialised. Tests therefore run without
Firebase. Event names follow Slidox:

`level_chip_tapped` · `level_selected` · `game_session_start` · `hint_used` ·
`level_completed` · `next_level` · `same_level` · `play_again` ·
`back_to_menu` · `game_abandoned` · `option_changed` · `options_restored` ·
`scoreboard_opened` · `scoreboard_cleared` · `options_opened` · `info_opened` ·
`language_changed`

Parameter values are strings or numbers; booleans are sent as 0/1.

To watch events live in the Firebase console's **DebugView**:

```bash
# Android
adb shell setprop debug.firebase.analytics.app com.tekinsight.sudoku
# iOS: in Xcode, Product → Scheme → Edit Scheme → Run → Arguments,
#      add -FIRDebugEnabled
```

`firebase_options.dart`, `google-services.json` and `GoogleService-Info.plist`
are generated by FlutterFire. To regenerate them, run:

```bash
flutterfire configure --project=sudoku-sagax-games --platforms=android,ios
```

Don't edit them by hand. iOS debug symbols are uploaded to Crashlytics by the
*FlutterFire: "flutterfire upload-crashlytics-symbols"* build phase in Xcode.

> **Patched build phase.** That phase has to find Crashlytics' `run` script.
> Flutter clones Swift packages into `build/ios/SourcePackages`, but the
> generated script only searched under `$BUILD_DIR` and DerivedData. With a
> custom DerivedData location this made `flutter build ipa` fail ("Could not
> find the Crashlytics upload symbols script"). The phase now checks
> `${SRCROOT}/../build/ios/SourcePackages/…` first. Re-running
> `flutterfire configure` regenerates the phase, so re-apply this patch
> afterwards.

## Localization

Uses Flutter's `gen-l10n` (configured by [l10n.yaml](l10n.yaml)).

- Source strings: `lib/l10n/app_<locale>.arb`; `app_en.arb` is the template.

Static HTML/CSS/vanilla JS site in [website/](website/), published at
<https://sudoku.sagax-games.com>, structured like the Slidox, Memorex and
MasterCode sites. The only build step is `node tools/build.js` (no
dependencies), which writes a static page per language; see "Languages" below.

```

  pt/ es/ fr/ de/   Generated copies of the three pages above; do not edit
  sitemap.xml       Generated, with hreflang alternates for every page
  robots.txt
  tools/build.js    Generates the language pages and the sitemap from js/i18n.js
  css/style.css     Sagax palette (same as lib/sagax_theme.dart) + the demo board
  js/i18n.js        All strings for the 5 locales; read only by tools/build.js
  js/main.js        Saves the language choice, screenshot lightbox, footer year
  js/sudoku.js      Playable Beginner sudoku, generated in the browser
  img/              Logos, favicons, social image (sudoku-sagax-og.png = feature graphic)
  img/screenshots/<lang>/   1_home, 2_game, 4_scoreboard, 6_info (Pixel 9 Pro shots)
```

### Languages

Every language has its own static page, so search engines index the
translated text without running JavaScript: English at the root (also
`x-default`), the others in `pt/`, `es/`, `fr/` and `de/`.

- **Editing text:** change `js/i18n.js`, or the HTML of the root pages (they
  are the templates), then run `node website/tools/build.js`. It rewrites the
  root pages in English, regenerates the four language folders and
  `sitemap.xml` (`lastmod` = the day it runs). Commit the generated files too.
- **Markup:** elements use `data-i18n="key"` (text), `data-i18n-html="key"`
  (static markup) or `data-i18n-alt="key"` (image alt). Dotted keys reach
  array items, e.g. `data-i18n="benefits.0.1"`; the build stops if a key is
  missing or if the template shows fewer benefits, features, screenshots or
  levels than `i18n.js` has. `img[data-shot]` gets the language's screenshot.
- **Generated per page:** `<html lang>`, title, meta description, `og:*`,
  canonical, `hreflang` links, the language switcher, each level's band and
  clue count (from `LEVELS` in `build.js`, which mirrors `sudokuLevels`), the
  demo's strings (`script#demo-text`) and the privacy policy text.
- **Automatic choice** (inline script at the top of each page, before it is
  painted): `?lang=` (old links, sagax-games.com) wins and is saved; then the
  saved choice (`localStorage` key `sudokusagax.lang`) redirects to that
  language's page. Only the English pages also follow the browser language.
- **Manual choice:** the language links save the choice and keep the current
  `#section`.

### Content

- **i18n.js:** the benefit texts, evidence note, tagline, difficulty names and
  game labels are copied from `lib/l10n/app_<locale>.arb`. The features list
  matches `docs/store-listing-texts.md`. Keep both in sync with the app.
- **sudoku.js:** ports the app's generator, so every demo puzzle has 46 givens
  and a unique solution. The level cards and the scientific references in
  `index.html` mirror `sudokuLevels` and the Info screen.
- **Privacy policy:** describes exactly what the app does. It uses Firebase
  Analytics and Crashlytics, with no Performance Monitoring, and keeps options
  and scores on the device. Update it if the Firebase setup changes. Its URL,
  <https://sudoku.sagax-games.com/privacy.html>, is the privacy policy URL in
  both stores (it redirects to the visitor's language).

Preview locally:

```bash
cd website && python3 -m http.server 8000   # http://localhost:8000
```

**Deploy:** the site is live. To update it, run `node website/tools/build.js`,
then upload the contents of `website/` (including `pt/`, `es/`, `fr/`, `de/`

## Publishing

First-time store setup (Play Console and App Store Connect records, privacy
declarations, listings, App Review information) and how the store assets are
made are in [docs/publishing.md](docs/publishing.md). This section covers each
new release.

### Before every release

1. Bump `version:` in [pubspec.yaml](pubspec.yaml). The format is
   `<version name>+<build number>` (e.g. `1.0.0+1` → `1.0.1+2`). **Both stores
   reject a build number that was already uploaded.**
2. `flutter analyze && flutter test`.
3. Smoke-test a `--release` build on a real iPhone and Android phone (see
   [Testing on a physical device](docs/publishing.md#testing-on-a-physical-device)).
4. Add the release notes to
   [docs/store-listing-texts.md](docs/store-listing-texts.md) (the *What's
   new* texts and the Google Play block).
5. If the release changes how the app looks, regenerate the affected store
   assets (screenshots, feature graphics, App Store artwork, video); see
   [docs/publishing.md](docs/publishing.md#store-assets).

### Google Play

```bash
flutter build appbundle --release
open build/app/outputs/bundle/release/      # app-release.aab
```

In Play Console, go to *Test and release → Testing → **Internal testing** →
Create new release*. Upload the `.aab`, paste the release notes block, and
roll out. Once it has been tested, promote the release to *Closed testing* or
*Production*.

### App Store

```bash
flutter build ipa --release && open build/ios/ipa/
# Sudoku Sagax.ipa
```

1. Upload the `.ipa` with Apple's **Transporter** app (drag and drop). The
   alternative is opening `build/ios/archive/Runner.xcarchive` in Xcode and
   choosing *Organizer → Distribute App → App Store Connect*.
2. After processing (usually 10–30 min), the build appears under
   **TestFlight**. Internal testers can install it at once; external testers
   need a short Beta App Review.
3. On the *App Store* tab, create the version, select the build, fill in
   *What's New* per language, check that the App Review Information notes are
   still there, and **Submit for Review**.

### Beta testers

Use **TestFlight** (iOS) and Play Console **internal testing** (Android).
Both take the same uploads as a store release.

## Original design brief (prompt)

Create a sudoku game named "Sudoku Sagax". Analyse memorex and slidox games and use similar architecture, UI and design. Investigate what are the main scientific papers that aply to benefits of sudoku type games. The game should have 9 dificulty levels, should have a timer, should have "notes" option (when notting the user can write small numbers in a cell, representing the possible numbers). As options screen with: sound ON/off; timer ON/off; show error (true/FALSE) if a wrong number is inserted; hint button (ON/off) a button to insert a correct number; defaults in CAPS. The game should have a scoreboard.
